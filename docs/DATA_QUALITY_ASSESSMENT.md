# Data Quality Assessment

## 1. Purpose

This assessment evaluates structural quality indicators in `data/canonical/intelligence_data.csv`. It does not independently prove real-world accuracy or source authenticity.

## 2. Results

The automated quality assessment evaluated 96 records. It reported unique record IDs, zero duplicate full rows, zero invalid coordinate rows, no unexpected pollutant subcategories, and an overall structural status of `PASS`.

Field-level missingness, numeric validity, timestamp validity, data-version consistency, source information, and synthetic-data flags are recorded in `data-science/outputs/quality_assessment.json`.

## 3. Quality Dimensions

* **Completeness:** Missing values are reported per field. Missingness must be interpreted in context because some fields may be optional for particular record types.
* **Uniqueness:** Record-ID uniqueness and duplicate full rows are checked.
* **Validity:** Numeric parsing, infinite values, timestamp parsing, coordinate ranges, and pollutant labels are assessed.
* **Consistency:** Data-version and pollutant-label consistency are checked.
* **Provenance:** Source labels and synthetic flags are profiled, but do not independently verify external provenance.
* **Accuracy:** Real-world accuracy is not independently verified.
* **Representativeness:** Assessed separately; balanced synthetic coverage is not proof of real-world representativeness.
* **Timeliness:** The three timestamps fall on one calendar date, limiting temporal coverage.
* **Reproducibility:** The assessment is generated by a versioned script against the canonical CSV.

## 4. Limitations

A structural `PASS` means the implemented checks passed; it does not mean every field is complete, every value is accurate, or every analytical track is suitable. Review field-level results in the generated JSON before relying on individual metrics.

## 5. Reproduction

```bash
python data-science/scripts/assess_data_quality.py
```

Output: `data-science/outputs/quality_assessment.json`.
